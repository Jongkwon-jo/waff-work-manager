# 2026-03-23 작업 정리

## 개요
- 전략기획사업부와 FA사업부의 업무관리/주간업무 흐름을 정리하고, 간트 뷰 및 주간업무 화면의 사용성을 개선했다.
- 공통 UI 재사용 범위와 DB 분리 구조를 점검했고, 숨김 상태 저장 정책도 일부 확장했다.

## 구조 확인 결과
- 전략기획사업부와 FA사업부는 같은 Firebase/Firestore 인스턴스를 사용한다.
- 간트 관련 주요 UI 컴포넌트는 공통으로 사용한다.
- 업무/프로젝트/이력/설정 데이터는 컬렉션 이름으로 분리되어 있다.
- `department_person_settings`는 공용 설정이며, 현재 FA 화면에도 동일하게 적용된다.

## 간트 뷰 개선
- 상단 월 표시 영역에 이전/다음 월 이동 버튼을 추가했다.
- `YYYY년 MM월` 클릭 시 드롭다운으로 연/월을 직접 변경할 수 있게 수정했다.
- 월 이동 UI를 `Project & Task Details` 위로 옮기고 더 작은 크기로 조정했다.
- 업무명 오른쪽에 기간을 작게 표시하도록 추가했다.
- 시작일과 종료일이 같은 경우에는 날짜를 하나만 표시하도록 수정했다.
- `엑셀 내보내기`를 선택형 UI로 변경했다.
  - 전체 프로젝트 출력
  - 특정 프로젝트 선택 후 출력
- 내보내기 시 화면에서 숨긴 프로젝트/업무도 함께 포함되도록 수정했다.

## 팝업/레이어 관련 수정
- 프로젝트 클릭 시 열리는 팝업의 잘림 이슈를 줄이기 위해 여러 레이어를 점검했다.
- `Dialog`, `Popover`, `Select`의 z-index를 상향 조정했다.
- 일부 sticky 영역의 overflow 설정을 조정했다.
- 전역 `html`, `body`에 `overflow-x: clip`을 적용했다.
- `엑셀 내보내기` 선택 UI는 최종적으로 팝오버가 아니라 다이얼로그 방식으로 변경했다.

## 숨김 상태 저장 정책
- 업무 숨김은 기존처럼 DB 저장 상태를 유지한다.
- 프로젝트 숨김도 공용 `project.isHidden` 필드로 DB에 저장되도록 확장했다.
- 새 프로젝트 생성 시 `isHidden: false`가 기본값으로 들어가도록 수정했다.

## 예외 처리 및 안정성
- `components/status-badge.tsx`에서 정의되지 않은 카테고리 값이 들어와도 에러가 나지 않도록 fallback 스타일을 추가했다.

## 주간업무 페이지 개발
- 메인 페이지에서 진입 가능한 주간업무 페이지를 사업부별로 생성했다.
  - 전략기획사업부 주간업무
  - FA사업부 주간업무
- 각 페이지는 해당 사업부의 업무관리 DB를 직접 참조한다.
- 초기에는 주간 캘린더 형태로 구성했고, 이후 일주일 간트 형태로 개편했다.

## 주간업무 데이터 표시 기준
- 업무관리 데이터 중 최하위 뎁스 업무만 표출하도록 변경했다.
- 숨김 처리된 프로젝트와 업무는 제외한다.
- `department_person_settings`를 참조해 사업부별 인원만 노출되도록 적용했다.
  - 전략기획사업부: `전략기획`, `ICT`, `기타`
  - FA사업부: `FA`
- 담당자 드롭다운을 통해 인원별 필터링이 가능하도록 구성했다.

## 주간업무 UI 개편
- 전체 색상을 간트 뷰와 어울리는 블루톤으로 정리했다.
- 좌측 목록은 프로젝트별이 아니라 인원별 섹션으로 구분되도록 변경했다.
- 좌측 업무 카드에서는 프로젝트 정보만 남기고 팀명, 기간, 담당자명은 제거했다.
- 우측 간트 바 내부에서는 업무명만 보이도록 단순화했다.
- 업무 클릭 시 프로젝트 상세 팝업을 띄우도록 연결했다.
- 요일 헤더는 `MM월 DD일`이 위, 요일이 아래에 오도록 정리했다.
- 오늘은 노란색, 토요일은 파란색, 일요일은 빨간색으로 강조했다.
- 세로 간격을 여러 차례 축소하고, 옅은 회색 세로/가로 격자를 추가했다.
- 마지막으로 좌측 업무 카드와 우측 캘린더 바의 세로 간격과 높이 기준을 맞췄다.

## 명칭 통일
- 전략기획사업부와 FA사업부의 업무관리/주간업무 페이지 명칭을 통일했다.
- 메인 페이지 카드 명칭도 사업부 기준으로 맞췄다.
